# 主流产品合同审查功能技术实现调研

> 调研主题：其他产品的合同审查功能是怎么实现的（技术实现视角）
> 日期：2026-10-08 ｜ 补充文档：与《市场调研结论.md》（商业视角）互补
> 资料来源：各产品官网与公开技术博客、LegalTech AI Hub/LegalAI Insights评测、幂律智能官方博客与CSDN技术文章、知乎技术专栏、公开报价与评测资料

## 一、执行摘要

主流合同审查产品的技术路线可分为四代：①规则引擎（关键词/正则/条款库匹配）；②监督式机器学习条款抽取（Kira、Evisort，标注语料+分类器）；③深度学习端到端审查（LawGeex的CNN流水线、Luminance模式识别）；④LLM+RAG/Agent（Spellbook、幂律PowerLawGLM、Harvey、DocuSign Lexion）。当前行业事实标准是"第四代为主、前代能力做底座"的混合架构：文档解析→条款切分→要素抽取→多路审查（规则基线+LLM研判）→结果回写Word。本报告逐产品拆解其实现细节，并在文末给出与ClauseGuard现状的对照与可借鉴点。

## 二、逐产品技术实现详解

### 1. Kira Systems（美国，已被Litera收购）——监督式ML条款抽取

- 核心管线：文档解析（自研PDF/Word解析，处理扫描件OCR）→段落级文本切块→监督式机器学习模型对每个段落做"是否包含某条款/信息项"的二分类→抽取值+定位原文段落。
- 模型形态：2015年起使用在数百万标注合同段落上训练的监督学习模型（早期为逻辑回归/SVM类文本分类器+特征工程，后迭代为深度学习句向量模型），预置1000+个"智能标准字段"（built-in models，如变更条款、责任限制、终止条款、各方主体、日期金额等）。
- 关键工程点：①不追求生成式"理解"，而是"定位+分类"，每条结果强制回链原文位置，可解释性强；②客户可用少量自有合同标注训练自定义字段（transfer learning，几百个标注样本即可)；③面向尽调场景批量处理（一次数千份合同的项目级审查）。
- 定位启示：Kira是"抽取器"而非"审查器"——它告诉你合同里有什么条款，风险判断留给律师。审查=抽取+人工规则叠加。

### 2. LawGeex（以色列）——深度学习审查流水线（经典学术路线）

- 其团队发表过公开技术论文（与学者合作的合同条款自动抽取基准研究），架构是典型的NLP流水线：
  ①文档解析与版式分析（PDF→带坐标的文本块）；
  ②条款分段：序列标注模型识别条款边界；
  ③条款分类：CNN/深度分类器把每个条款归到预定义类型（保密、赔偿、管辖、终止等数十类）；
  ④与"审查政策（playbook）"比对：企业预先定义每类条款的可接受标准（如"赔偿上限不超过合同金额"），模型判定符合/缺失/偏离；
  ⑤输出三态结论：ok / missing（缺失条款）/ deviation（偏离标准），并高亮原文。
- 关键工程点：审查标准以结构化playbook表达，实现"自动化但不黑箱"——每条结论都能追溯到"哪类条款+哪条政策"。LawGeex宣称的审查速度（几十秒/份）与准确率（对标资深律师的盲测）即基于此流水线。
- 定位启示：LawGeex证明了"playbook驱动的三态判定"是企业客户最认可的可解释审查形态。

### 3. Luminance（英国）——模式识别+语义聚类

- 技术路线：自研"Legal-grade LLM"之前，以无监督/半监督模式识别著称：对全合同库做语义聚类，自动发现条款的常见形态与异常形态（anomaly detection），审阅者第一眼看到的是"这份合同的条款分布与历史库的偏离"。
- 审查实现：①ingestion阶段统一解析（含扫描件，集成OCR）；②每份合同自动生成"审查摘要面板"（按条款类型分组，异常标红）；③negotiate模块：多轮谈判版本间自动diff，标注对方改了什么、改动是否引入新风险；④后续叠加LLM做问答与起草。
- 定位启示：Luminance的差异点是"用企业历史合同做基线的异常检测"，即"偏离度审查"，适合审查量极大的尽调与合规团队。

### 4. Evisort（美国，2024年被Workday收购）——Document AI批量抽取

- 核心是自研OCR+合同专用NLP：扫描件→OCR还原→150+条款类型的实体/数值抽取（义务、金额、到期日、自动续约、单方解除权等）→结构化入库，支持对整个合同库做跨文档查询与到期/义务台账。
- 审查部分同样是"抽取+规则校验"（如到期日无续约提醒=风险），偏存量资产分析而非单份审查流程。
- 定位启示：把审查产出沉淀为结构化台账（义务/日期/金额），是产品从"一次性审查"走向"持续价值"（续费）的关键。

### 5. Ironclad / DocuSign CLM（含Lexion）——流程内嵌的AI审查

- Ironclad：审查AI嵌在CLM工作流里——起草时Workflow Builder按合同类型路由到对应模板与条款库，AI Repository自动抽取要素入库，审批流中AI做"是否符合我方模板"的偏离检查（红线比对）。
- DocuSign Lexion：基于OpenAI的合同摘要、义务抽取、续约提醒，能力偏"理解与提醒"，嵌入电签闭环。
- 定位启示：审查不是独立页面，而是拆散嵌进起草/审批/履约各环节，每处只做"当时最必要的一个AI动作"。

### 6. Spellbook（加拿大）——Word插件+多LLM编排（LLM时代代表）

- 形态：纯Word加载项（add-in），无独立网页端。审查发生在律师的原文档里。
- 实现要点（据官网与评测）：
  ①多模型编排：同时使用GPT-5、Claude等多个LLM，按任务路由（起草/红线批注/问答用不同模型），不依赖单一模型；
  ②Playbooks功能（2025年推出）：把公司标准谈判立场编纂成结构化规则，AI审查时自动按"我方立场"逐条检查并生成修改建议；
  ③红线修订：AI直接以Word修订模式（track changes）插入建议措辞，律师逐条接受/拒绝；
  ④上下文工程：整份合同+所选playbook+条款类型识别结果组装进提示词，长合同做分段映射。
- 定位启示：LLM审查的体验关键不在模型而在三件事——playbook结构化、Word内原生交互、多模型冗余。

### 7. 幂律智能MeCheck（中国，清华NLP团队）——审查点体系+垂直大模型

- 官方公开的技术叙事（官网/CSDN/知乎专栏）：
  ①审查点知识体系：以法律知识图谱为指引，把"审查"拆解为40+合同类型、1000+审查点，每个审查点=检查逻辑+法条依据+建议措辞，这是其最核心资产；
  ②NLP基座→垂直大模型：2019年起用NLP做审查，后自研PowerLaw-GLM法律大模型（清华系），用海量法律语料继续预训练+审查场景微调；
  ③Agent化（2025-2026公开方向）："MeCheck Agent"将大模型能力拆为规划→逐条款审查→工具调用（法条检索/计算）→自检的智能体流水线；
  ④交付形态：审查结果以批注直接落到Word，支持版本比对；企业版私有化部署（本地模型+本地知识库）。
- 定位启示：国内可对标的头号竞品。其壁垒是"审查点库"（法律工程）而非纯模型，与大模型是互补关系。

### 8. 法大大/腾讯系、通义法睿（中国大厂系）

- 法大大"合同智审"：规则引擎（内置数十种合同类型的必备条款/风险条款校验）+AI抽取混合，输出以"风险提示清单"为主，深度中等；强项在电子签闭环、等保三级与渠道。
- 通义法睿：通用大模型直接做合同初筛与问答，浅审查、无审查点体系与流程，作为生态入口免费铺量。
- 定位启示：大厂系用"规模+闭环+低价"打市场，审查深度刻意留白——这正是垂直审查产品的生存空间。

## 三、跨产品共性：审查功能的通用技术架构

各代产品殊途同归，当前业界收敛出的标准管线是：

1. 文档解析层：PDF/DOCX/扫描件→结构化文本。扫描件OCR（PaddleOCR/LayoutLMv3类）是隐形门槛，解析质量决定审查上限。
2. 结构化层：条款切分（标题识别+序列标注）→要素抽取（主体/金额/日期/管辖/争议解决）→合同类型分类（路由到对应审查规则集）。
3. 审查引擎层（多路并行，结果融合）：
   - 规则基线：必备条款清单校验（缺失类风险）+硬性合规规则（正则/逻辑）——保证召回下限、可测试；
   - LLM研判：RAG召回法条/审查点→大模型逐条款给风险定级+修改建议+依据——提供语义理解与措辞级建议；
   - 基线比对：与企业范本/playbook做差异审查——准确率最高的审查方式；
   - 溯源过滤：无召回依据/低置信度的LLM输出直接丢弃（防幻觉），这是企业客户敢用的前提。
4. 交付层：结果以Word批注/修订回写原文（OOXML comments），而非仅网页列表；版本间条款级diff；审查台账与审计留痕。
5. 反馈闭环：人工确认/驳回记录回流，做评测集与提示词/模型迭代（数据飞轮）。

## 四、对ClauseGuard的对照与可借鉴点

ClauseGuard已具备的对应能力：文档解析（pdfplumber/docx）、条款切分、要素抽取（正则+LLM交叉校验）、规则引擎基线、RAG法条召回+LLM研判、逐条款溯源召回+置信度过滤、批注回写Word、版本diff、审计留痕、人工修正记录落库。管线形态与业界标准架构基本对齐，处于"第四代混合架构"的1.0完成态。

对照头部产品，最值得借鉴的五点（按优先级）：

1. Playbook/审查点体系化（Spellbook Playbooks、幂律1000审查点、LawGeex三态判定）：把rules.json升级为"合同类型→审查点→判定标准（符合/缺失/偏离三态）→法条依据→建议措辞"的结构化审查点库，这是所有头部产品共同的核心资产，也是审查准确率的第一决定因素。
2. 版式解析补强（Kira/Evisort/Luminance均自研OCR）：集成PaddleOCR处理扫描件PDF，纳入70%的存量扫描合同。
3. 企业范本基线审查（Luminance异常检测、Ironclad偏离检查）：以企业上传的范本为基线做"偏离度审查"，比自由审查准确率高，且把客户知识沉淀进产品形成粘性。
4. 多模型冗余与路由（Spellbook多LLM编排）：审查关键路径用双模型交叉验证（现有LLM_CROSS_*配置已预留），并支持按任务路由不同运行时（ollama/vllm/openai已在系统设置中支持）。
5. 审查结果台账化（Evisort）：把每次审查的义务/日期/金额抽取结果沉淀为跨合同台账（到期、续约、义务提醒），从单次审查工具升格为持续使用的平台。
