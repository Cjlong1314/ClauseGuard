# ClauseGuard等保三级（网络安全等级保护第三级）建设路径

依据《GB/T 22239-2019 信息安全技术 网络安全等级保护基本要求》第三级系统要求整理。适用对象：ClauseGuard私有化部署（央国企/金融客群投标场景）。定位：合同数据属"内部敏感数据"，建议按三级定级备案（技术+管理双清单）。

使用说明：下表"现状"列基于ClauseGuard当前实现；"差异项"为与三级要求的差距；"整改清单"为落地动作（P1=随部署包默认交付，P2=客户侧实施项，P3=测评前专项）。

## 一、安全物理环境

| 要求项 | 现状 | 差异项 | 整改清单 |
| --- | --- | --- | --- |
| 机房出入控制（电子门禁） | 客户机房/云机房 | 依赖客户 | P2：查验机房等级（三级要求B级及以上）、门禁记录留存≥6个月 |
| 防静电/防火/防水/温湿度 | 同上 | 依赖客户 | P2：现场核验并留存机房检测报告照片 |
| 电力供应（冗余UPS） | 无 | 双路供电/UPS需确认 | P2：要求客户提供UPS供电证明；云部署要求可用区≥99.95%SLA |

结论：私有化部署物理环境责任在客户，交付物为《机房环境核验表》模板（实施顾问随包提供，见deploy/docs）。

## 二、安全通信网络

| 要求项 | 现状 | 差异项 | 整改清单 |
| --- | --- | --- | --- |
| 网络架构划分（生产/管理/办公分区） | 单机部署默认同网段 | 缺分区 | P1：部署文档提供三区网络拓扑建议图；P2：客户侧VLAN/安全域划分 |
| 通信传输完整性/保密性 | 应用未默认HTTPS | **差异：默认HTTP** | P1：compose前置Nginx TLS终结配置示例+自签/国密证书说明；P2：客户签发正式证书（国密场景SM2双证） |
| 关键链路冗余 | 单点 | 无冗余 | P3：双机+负载均衡（等保测评对三级要求关键链路冗余，单机部署需在测评中说明风险接受或加F5/LVS） |

## 三、安全区域边界

| 要求项 | 现状 | 差异项 | 整改清单 |
| --- | --- | --- | --- |
| 边界防护（访问控制策略） | 无防火墙策略默认全通 | **差异** | P1：部署包附iptables/firewall示例——仅放行8600(HTTPS)/5432限内网/22限跳板机 |
| 入侵防范 | 无IDS/IPS | **差异** | P2：建议客户侧部署HIDS（如青藤/安全狗/OSSEC）；云上开WAF |
| 恶意代码防范 | 镜像无扫描 | 差异 | P1：交付前trivy镜像扫描报告（随包附）；P2：客户侧主机杀毒 |
| 接入外部网络边界（上网行为） | 不涉及 | — | 服务器不开外网出口，离线化即满足 |

## 四、安全计算环境（重点：ClauseGuard应用自身）

| 要求项 | 现状 | 差异项 | 整改清单 |
| --- | --- | --- | --- |
| 身份鉴别（口令策略） | PBKDF2口令散列✅、2小时Token✅、登录锁定✅ | 缺口令复杂度策略 | P1：注册接口加复杂度校验（≥8位、三类字符）；P2：接入客户AD/LDAP或双因子 |
| 访问控制（RBAC） | 四角色RBAC✅ | 微调 | P1：管理员操作二次确认+审计 |
| 安全审计 | 全量审计留痕✅ | 审计日志防篡改 | P1：audit表追加only-append（revoke update/delete）；P2：审计日志异地归档（syslog转发客户SIEM） |
| 剩余信息保护 | Token过期✅ | — | P1：登出即销毁服务端Token（已实现logout） |
| 数据保密性（存储） | **明文存储PG** | **差异：缺AES-256存储加密** | P1：方案5.2要求——uploads目录加密（Fernet/SM4）+PG敏感字段加密扩展pgcrypto；密钥由KMS/环境变量注入 |
| 数据完整性 | PG约束✅ | — | 增加每日备份校验（pg_restore --list比对） |
| 数据备份恢复 | backup脚本✅ | 恢复演练记录缺失 | P2：每季度恢复演练并留存记录（测评必查） |
| 入侵防范（主机层） | 依赖客户 | 同区域边界 | P2：最小化安装、关闭无用端口、及时补丁（客户侧基线核查表） |
| LLM推理安全 | RAG溯源闸门✅置信度✅ | 提示词注入风险 | P1：流水线judge阶段对条款文本做注入特征过滤；输出免责声明+人工确认（已实现） |

## 五、安全管理中心

| 要求项 | 现状 | 差异项 | 整改清单 |
| --- | --- | --- | --- |
| 系统管理（账号管理） | admin可管理✅ | 缺三员分立 | P2：等保三级要求系统管理员/安全管理员/审计管理员三员分立——将现有admin/reviewer/auditor角色映射为三员，禁用admin一人多角 |
| 集中管控（日志集中） | 本机日志 | **差异** | P2：rsyslog/syslog-ng转发至客户日志平台；容器日志轮转（compose logging: max-size 50m, max-file 10） |
| 漏洞与补丁管理 | 无 | 差异 | P2：季度漏洞扫描（ Nessus/绿盟）+修复记录 |
| 态势感知 | 无 | 测评建议项 | P3：客户侧SOC对接 |

## 六、管理要求（制度文档清单，实施顾问交付模板）

1. 安全管理制度总纲+发布记录（P1模板随包）
2. 人员安全管理：保密协议、离岗账号回收流程（P2）
3. 系统建设管理：定级备案表、方案评审记录、上线安全评估（P1定级备案为前置）
4. 系统运维管理：变更管理流程、备份与恢复制度（对应本包backup脚本）、事件应急预案（含LLM服务不可用降级预案，P1）
5. 安全事件处置：上报流程与演练记录（P2）

## 七、信创服务器适配评估

| 评估项 | 结论 | 说明 |
| --- | --- | --- |
| CPU架构（鲲鹏/飞腾ARM、海光/兆芯x86、龙芯LoongArch） | x86✅直接可用；ARM✅需验证；LoongArch⚠ | Python生态x86/ARM均成熟；风险点在编译型依赖（lxml、psycopg2-binary需ARM轮子或源码编译——psycopg2-binary提供aarch64，lxml有manylinux aarch64轮子，理论可行，需在目标机上实测pip install） |
| 操作系统（麒麟V10/统信UOS） | ✅Docker可用版直接兼容；无Docker环境用裸机uvicorn+systemd部署（deploy.sh备用路径见README） | 麒麟V10 SP2+自带containerd/docker-engine |
| 数据库（人大金仓/达梦/瀚高） | ⚠非本期 | PG协议兼容的金仓可低成本迁移（db.py为标准SQL），向量降级路径同样适用；列为二期评估项 |
| 国产LLM | ✅天然适配 | Qwen2.5/DeepSeek为国产开源模型，Ollama/vLLM均支持；vLLM在ARM GPU（昇腾910B需vllm-ascend插件）为适配风险点，建议客户昇腾环境改用Ollama+Q4量化CPU/GPU推理或申请适配验证 |
| GPU（昇腾910B） | ⚠ | nvidia-container-toolkit不适用；走vllm-ascend社区版或CANN+MindIE；POC阶段建议先用NVIDIA/国产x86+GPU环境验收，昇腾作为专项适配 |
| 中间件（东方通TongHTTP等替代Nginx） | 可选 | TLS终结可用TongHTTPServer替代，配置等价 |

信创结论：x86国产化（海光+麒麟+金仓）路径风险最低，可承诺；ARM（鲲鹏+麒麟）次之，需部署演练；昇腾GPU推理为最大适配风险，建议合同中列为专项验证条款，先评估后承诺（对应方案七风险应对）。

## 八、整改优先级总表

- P1（随部署包默认交付）：HTTPS配置示例、防火墙策略、口令复杂度、审计防篡改、存储加密方案、trivy报告、制度模板、应急预案
- P2（客户实施/实施顾问陪跑）：机房核验、分区网络、正式证书、IDS、三员分立、日志集中、恢复演练、AD/LDAP
- P3（测评专项）：链路冗余、态势感知、昇腾适配验证
